## What it is

A folder you copy to the old PC with a USB stick. In it, **`RUN-TEST.cmd` is the one file Orb double-clicks.** It is a batch file with PowerShell and the test page inside (plain text, readable). Beside it: `game\` (the web build), `project\` (the sim and its data, 9 MB, no art), `godot\` (the two Godot executables, 173 MB, copied from the editor install on this PC, not downloaded) and `README.txt`. About 230 MB.

It runs two parts and writes **one file, `oldpc-result-<date>-<time>.json`, next to itself**, which Orb brings back:

1. **No window, no picture (about 2 to 3 minutes on this PC), in two steps.**
   - **1a, Netcode's two-PC check** (`net/tools/two_pc_check.gd`, parked in `docs/net/pending/two-pc-check/`): a match and a rematch in one process and a 106-line text report of check numbers, plus `tick_ms` and `snapshot_ms`, the old PC's first real rollback numbers. **This is the two-processor result.** It runs at below-normal priority, as Netcode's own kit does.
   - **1b, the speed run** (`oldpc_sim.gd`): three planets × (a first match and a rematch) × 7,200 ticks on that processor: every tick's time (mean, p50, p95, p99, max, ticks over 16 and 33 ms, the ten worst), the match build time and a fixed float64 job. It also keeps the gameplay hash every 120 ticks, which adds two more planets to Netcode's one; Netcode's report is the verdict and mine is a cross-check that can be dropped.
2. **The game in the browser (about 4 minutes).** The test page of the earlier steps (notes, one Start click, the game's own flashing-effects warning, 120 s of play, frame times, graphics names, a verdict), served from `127.0.0.1` by the batch file itself.

Then **`compare-results.mjs <main PC's file> <old PC's file> --project <a tree with net/tools/two_pc_check.gd>`** (on this PC) hands the two embedded two-PC reports to Netcode's own compare (`THE SAME`, exit 0; `DIFFERENT ... first disagree in match A at tick 540`, exit 1; `NOT COMPARABLE`, exit 2; without `--project` it prints the command), and prints for my speed run `agree` or `DIFFER at tick N` per match, the two speeds side by side and the ratio of the fixed job. Run the same kit folder on the main PC too (the same `RUN-TEST.cmd`) to get the other file.

## No prompt, no network, no download

- It listens on **127.0.0.1 only**, on the first free port of 8790 to 8799: no firewall prompt (loopback), no administrator rights, no installation, no network link, nothing uploaded. Godot headless opens no socket. The old PC needs neither Node nor Python.
- It opens the default browser on its own page (a window, not a prompt). If Windows shows "protected your PC" it is the usual warning for a file that came from the internet; a file copied by USB does not get it.
- **What the old PC gets from this PC is a copy, by hand:** the folder includes Godot's own executables copied from this PC's editor install (MIT-licensed). If Orb does not want that on the old PC, Part 1 is skipped by deleting the `godot` folder (the page part still runs; the two-processor check does not).
- Godot keeps a small log under the user's AppData on the PC it runs on. Nothing else is written outside the kit folder (the `parts` folder inside it holds the sim's own file; delete it after).

## For the EP: making the kit (after the commit has World's rematch fix)

```bash
node tools/preview/stack-preview.mjs --no-serve
node docs/perf/oldpc/kit/build-kit.mjs --site "%LOCALAPPDATA%\Temp\meridian-stack-preview\live" --out C:\path\to\a\new\empty\folder [--build <commit>]
```

`--build` defaults to the tree's short commit and goes into the batch file; it must be the same on every PC taking part, which one folder copied to both guarantees.

The second command copies the game, the repo's `sim/` and `data/` (so run it on the tree you want measured), the Godot executables, and lets Godot import the project once so the old PC does not have to (the batch file also does that itself if the `.godot` folder is missing, about a minute). It takes about 2 minutes and 230 MB.

## Plain steps for Orb

On this PC: nothing, the kit is a folder. (If you want the main PC's file too: double-click `RUN-TEST.cmd` in the same folder here first, and keep the result file it writes.)

1. Copy the whole folder to the old PC with a USB stick. Plug the old PC in the wall, close games and other browser windows. Monitor into the graphics card (the GTX 1080).
2. Double-click `RUN-TEST.cmd`. Read the first screen (only you watch; no photos, screenshots or recordings) and press Enter.
3. Wait two or three minutes (a black window with lines of numbers). Then your browser opens a page: press **Start**, read the game's **flashing-effects warning** (Reduce flashing is there if you want it), click **I understand, start** (and close any how-to card), then **leave the mouse and keyboard alone for two minutes**.
4. The page says **Done**; the black window says "Bring this ONE file back" and names it. Copy that `oldpc-result-….json` to the USB stick and bring it back. Delete the folder if you like.
5. For the built-in graphics (HD 530), if the board has a video port: turn the old PC off, move the monitor cable to the board's port, and run `RUN-TEST.cmd` again (the result names the graphics it ran on; a second file is made).

## Limits

- **Not run on the old PC, not run on a second processor**: the cross-processor agreement is untested until the file comes back; on one PC two processes agree. A first LAN test is still version 1 as `docs/net/two-v-two-lan.md` says.
- **The kit must be built from a tree that carries Netcode's park** (`docs/net/pending/two-pc-check/`, files `net/tools/two_pc_check.gd`) **and World's `contact-surf-derive`**, and one folder must run on both PCs (the build name is inside the batch file; the check refuses reports of different builds). `build-kit.mjs` says so when the check is missing and then builds the speed part only. The kit tried here was built from a scratch copy of the EP's `s400` with the park applied (build name `s400-trial`), which has contact-surf-derive; it has now been built from the committed tree dafc348f (section above).
- Netcode's check has only ever run on this PC, so a pass here shows the check works, not that two PCs agree.
- The page and the game ran in headless Chrome here; Edge or Chrome with a window on the old PC differ in timing, not in logic. The default browser opens: if it is neither Chrome nor Edge (Firefox), the game may not start; the steps say Chrome or Edge.
- The kit's sim part plays the stack as the `project\` folder holds it, which may differ from the web build in `game\` if the two were built from different commits; `build-kit.mjs` takes both from what it is given, so build them together.
- Part 1 uses the headless Godot console build for Windows; a different OS needs its own.
