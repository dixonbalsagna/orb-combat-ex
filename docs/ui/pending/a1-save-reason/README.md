# a1-save-reason: "Save this match" tells the host it is a save (S-42; UI & UX, 2026-11-20; park, not landed)

Tools' recorder (`report-hook.patch`, docs/tools/pending/code-03/, 82e910fc) never prunes a file saved with the reason `save`, but nothing sent that reason: the HUD's three save paths all reached the host as a plain report, so a player's "Save this match" still counted toward the cap of 20 and could be deleted. The reason was lost in two places, so the fix is two small pieces:

- `save-reason.patch` (`patch -p1` / `git apply`; **UI, ui/ only**; **re-cut 2026-11-20 on the GW1a stack: dry-run clean on the files of `s422`, which ends at `a1-rail-default`**; `a1-world-menu` and `a1-window-row` are re-cut on top of it, so apply them after it): `ui/hud/ui_hud.gd` gains `_report_save(tags, note, reason)`: a hook that takes a third argument gets the reason, a hook of two arguments (the LAN hook) is called exactly as before. `save_match()` sends `"save"`; F9 and the feedback panel's SAVE REPORT still send nothing extra and stay reports. `ui/tools/hud_check.gd` has `_save_reason_rules`: a host whose hook takes a reason sees `["", note, "save"]` from Save this match, F9 stays `report`, the panel's save stays `report`, and a two-argument hook is called with two. Negative control: with the reason put back to `report` the first rule fails.
- `grant/main-gd-record-report-reason.patch` (**Rendering's `render/core/main.gd`; needs a grant**, 2 changed lines, cut on the GW1a stack copy: it applies there, not to HEAD until code-03 lands): `_record_report(tags, note, reason := "report")` passes the reason to `host.record_file(reason, tags, note)`. Without it the host still hard-codes "report" and the UI's reason is ignored (harmless, but the player's save stays prunable).

Gate: the Rail and A1 rules with the new rule, 816 checks, 0 failed (partial; the change is one function and one call). Land the two together, with GW1a.
