# Park (GW1b, after the flip): four World checks that fail on the full GW1b stack, classed and fixed (World, 2026-11-21; EP's gate item on s426)

On the EP's full GW1b stack (scratchpad `s426`, all owners' GW1b data and the flip) `world-checks --run` failed four checks. I took a copy, reproduced them, and bisected by applying the other owners' patches in groups onto clean main (the checks pass after the first eight steps, which are World's and the strip-arena pins). **None is a fault in the game; each is a check written for a number or a rule that GW1b changes on purpose.** Two causes are other owners' (named), all four fixes are World's check files: `gw1b-checks-reread.diff`, strict on the s426 state (it needs `pin.gd` as `pins-gw1b.diff` leaves it).

| Check | Rows | Cause (owner) | Class | Fix |

Proof of each cause, from the bisect (World's scratch `v2`, main + the patches of `docs/world/runs/gw1b-checks-reread/`): `beam_grid_check` and `wall_check` pass after steps 1 to 8; `wall_check` fails after steps 9 to 14 and passes again with `gw1b-energy`'s three patches reversed, and fails with its `grant-data-gw1b.patch` alone; `beam_grid_check` passes through step 16 and 17 to 26 fail it, and reversing only `stray-beams.diff` (and its input patch, not the other patches of the group) clears it, with a probe showing `fireTick -1` against 48. A probe with `dropOnPress` off still does not fire: it is the RT + B window, not the drop.
