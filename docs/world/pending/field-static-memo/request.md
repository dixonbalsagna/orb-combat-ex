# Request to Simulation: a static memo in SimField (World, 2026-11-02)

**What.** `SimField.col` (sim/core/field.gd) memoises a strip column's ground per `_serial`: sample (the planet's field) + `WorldField.applyRecords` (lots, pads, platforms) + `WorldStore.heightDelta` (craters, scorches, trenches), all in one number. With `field-place` a record joining the store clears the columns it can reach, and each of those is then read again **in full**. Only the last term depends on the store. The first two depend on the frame (seed, point, tangent, x0) and on `S.fieldRecs` (fixed once the match is planned), so they can stay.

**The change (Simulation's file, so a grant).** In `field.gd`: a second memo pair `_m1s`/`_s1s` (the ground before the store's delta) valid for a `_frameSerial` that moves in `_bind` for a new frame, seed, column count or `S.fieldRecs.size()` but **not** for `storeHash`; `col()` reads `_m1s` if valid, else computes sample + applyRecords once and stores it; then adds `heightDelta` if `S.storeN > 0` and fills `_m1` as today. `storeGrew`'s targeted clears keep clearing only the full memo (`_s1`), never `_s1s`. The far read's `_coarse` the same (`_m0s`). About 25 lines and two or three arrays; one check (the full read equals the split read bit for bit across a run of digs and a swing).

**Hash: neutral.** `_ground` is `h = sample; h = applyRecords(h); h += heightDelta`; the split keeps that order, so every value is bit-identical. Orb's replays reproduce.

**What it buys (Orb's first play, native, below normal, shared PC, field-place and water-read beneath, 309 to 421 columns re-read by a window step).** A re-read after a record pays today about 45 microseconds a column of which `sample` 8.5 (warm nodes), `applyRecords` about 10 and `heightDelta` about 11, `pointAt` 4, the memo and call overhead the rest; with the split it pays `heightDelta` plus a lookup, about 13: **about three to four times cheaper**, so a window step during a beam falls from about 8 ms (the first flow step after the warm) to 2 to 3 ms, and the beam's trench columns (which are exactly the columns the beam's records void) stop being the cost. It does nothing for the first read of ground the match has not read (cold nodes: 20 ms in the first window): that is what `water-window-warm` spreads. See `docs/world/water-read.md`.

**Not measured:** the split itself (I have not built it); the numbers above are the parts I timed (`FT` timers in a scratch copy of Orb's replay tree), added up.
