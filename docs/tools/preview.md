# The private preview: the new planet, playable in Orb's own browser (Tools, 2026-10-30)

Owner: Tools and Pipeline. Asked by the EP for Orb's push of 2026-10-30 ("get the new planet ready for Orb to play"). **Private and local: nothing is published, uploaded or dispatched, the live pin and `tools/site.json` are not touched, and no work in progress goes on a public page.**

```
node tools/preview/preview.mjs                     build main with every new-planet switch on, check it, serve it on 127.0.0.1:8765, print the URL
node tools/preview/preview.mjs --off water,floor   the same with those switches off (to compare); "--off all" is the plain build
node tools/preview/preview.mjs --list              the switches and what each does
node tools/preview/preview.mjs --check             do the switch table and the scratch patch still fit this tree? (no Godot, no browser, writes nothing)
node tools/preview/preview.mjs --overlay sim/input,data/input,docs/controls/pending/right-hand --open
                                                   the same with the right-hand work of the WORKING tree (not committed yet) laid over main, and the page opened in your default browser
```

Other flags: `--planet 7` (the planet's seed in the printed URL), `--port 8765` (a busy default falls on to the next; a port you name must be free), `--rev main`, `--no-smoke`, `--no-serve` (build and check, then exit), `--rebuild`, `--bisect`, `--godot <exe>` (else `$GODOT`, else the usual 4.7.2 install), `--out <folder>`.

Open the printed URL in Opera. To compare, run the command a second time in another terminal with `--off <switch>` and `--port 8766`, and open both.

## What it does

1. Unpacks the **committed** tree of `--rev` (default `main`) into a scratch folder under the temp folder (`meridian-preview/<commit>-<switches>-<patch>/`). Uncommitted work in the checkout is not in it.
2. Turns the switches on **there only**, by editing the data files' text (the one value, the rest of the file as it was):

| id | file and key | what it is | needs |
| :--- | :--- | :--- | :--- |
| `gen2` | `data/biomes/climate.json` `gen` 1 → 2 | planet generation 2 for every planet match | |
| `biome` | `data/combat/launch_biome.json` `biome.enabled` | the launch planner reads the ground | |
| `water` | `data/biomes/water.json` `enabled` | water v2 | |
| `surface` | `data/biomes/water.json` `surface.enabled` | surfacing, world half | |
| `interrupts` | `data/director/interrupts.json` `water.enabled` | surfacing, director half | |
| `floor` | `data/biomes/water.json` `floor.enabled` | the lake floor | `surface` and `interrupts` |
| `turn` | `data/biomes/rings.json` `turn.on` 0 → 1 | the arena's calm turn: the ring swaps for a new one, turned a few degrees | |

   `turn` (the EP, 2026-10-30; `--off turn` for the plain ring) is on by default so the ring turn can be seen in play. A turn needs a **planet match** (the preview's `?planet=` start), **60 s of match time since the last turn** (`turn.gapSeconds`), and **a calm moment after a launch has landed** (both fighters down or set, nothing moving); a match turns at most 4 times, each by at most about 10 degrees. So the smoke check (20 s of keys) does not wait for one: it checks that the running game reads the switch as asked and prints the match's turn count (`turns` in the probe, -1 when the match cannot turn). To see a turn, play a planet match for a minute or two and land a launch.

   `floor` needs both halves of the surfacing rule or the game's own load check (`WorldFill.floorProblem`) refuses it, so `--off surface` or `--off interrupts` turns the floor off with it, and the report says so. Rivers and B plates (`rivers.json`, `land.json` `b.enabled`) are **not** in the set: the EP's list did not name them, and World's readiness note holds them for Orb's look. They are two more rows in `tools/preview/switches.mjs` if wanted.
3. **Scratch code, two small patches to `render/core/main.gd` of the scratch copy** (`tools/preview/switches.mjs`, `patchMain`): a **`?planet=N` entry**, because the shipped game builds a generated planet only when a match's setup names one and neither the start menu nor the URL does yet (so `gen` alone changes nothing a player sees: a normal start plays the hand-made world); and a **`?preview=1` probe** that publishes `window.__preview` (tick, planet generation, what each switch reads as in the running game, hit points, the water loader's errors) twice a second for the smoke check. The printed URL carries `?planet=N`; without it Orb plays the hand-made world, where only the biome and water switches act. Each patch anchor must be found exactly once, or the build stops and says which line changed.
4. Imports and exports the Web build with the **standard** export template, single Godot process, at below-normal priority, 25-minute limit each. The custom template and its pin are not involved.
5. Runs the **boot-and-play smoke check** (`tools/preview/smoke.mjs`) through the guarded browser launcher of `tools/machine/browser.mjs` (time limit, below-normal priority, CPU cap, profile folder `cap-tools-preview-…`): the build boots; the check clicks through the first-run How to play card and the start menu ("I understand, start") as a new player would, then sends keys for 20 s; it raises no script exception or console error, the match's tick runs on, a canvas is drawn, and **every switch reads in the running game as it was asked** (a switch that reads off when it was turned on is a failure). A failure names the switch the evidence points at; `--bisect` then builds and checks each switch alone.
6. Serves the folder on **127.0.0.1 only**, no cache, until Ctrl-C.

A build is cached by commit, switches and patch: the same command again serves at once and prints the smoke result recorded with the build. `--rebuild` builds again.

Time on this PC (below-normal priority, other sessions running): about 45 s to import and export, about a minute and a half for the smoke check, a cached build serves at once. The first start in the browser shows the game's own flashing-effects notice and the How to play card, as any fresh visitor sees them.

## What it does not do

- It does not start a browser for Orb; it prints the URL.
- It does not prove the look. The smoke check proves the game boots, plays and has the switches on; Orb's eyes judge the planet.
- A planet match on gen 2 builds its planet in one synchronous call at match start (World's readiness note: about 1.1 s native, more in a browser), so the start may pause longer than the hand-made world's.
- The preview is not the public build: nothing here goes through the site job, the release pass or the flash check, and the build must never be copied to a public page.

## Tests

`node tools/preview/preview-selftest.mjs [--require-browser]` (CI, the qa job): the edit of each switch on fixture files shaped like the real ones, the cascade, the patch (LF and CRLF, a missing or doubled anchor), the whole build against a throwaway repository with a stand-in for Godot (**the repository comes out untouched**, `tools/site.json` byte for byte, the scratch tree flipped and patched, `--off` building elsewhere, a failed export showing its log), the local server (127.0.0.1 only, no path out of the folder), and the smoke check on tiny pages (passes a page that reads as asked, fails one whose water reads off and names `water`, fails a page that never publishes). `--check` is the real-tree twin: run it after any change to those data files or to `render/core/main.gd`.

## The right hand, and switches that are not in the tree yet (the EP, 2026-10-31: Orb's night order, "a working version with the 3d world and our new controller mapping folded in")

- **`rightStick`** is the eighth switch: `data/input/timing.json` `switches.rightStick` false to true (Controls' pitch 4a: the right stick throws directional-charge strikes, the left hand braces and slips). It needs two things in the tree you build: Controls' code and data (`sim/input/`, `data/input/`), and **the pad's right stick read by `render/core/main.gd`**, which is Controls' `right-hand-host.patch` until Rendering lands it. The preview applies that patch to the SCRATCH copy of main.gd when the tree has not got the change (`docs/controls/pending/right-hand/right-hand-host.patch` in the tree you build or overlay); with neither the change nor the patch the switch WAITS and says why, and the build is made without it. The probe (`?preview=1`) reads `SimInputData.right_stick_on()` and the smoke check expects it as asked.
- **A switch that waits is never a pass.** A switch whose key is not in the tree you build (the file is missing, or the key) is listed as `WAITING, not in this build` in the report, `--list` and `--check`, is not on, and is not counted as checked. A key that is there with a value the table does not know is an error, as before. `tools/preview/switches-pending.json` holds names that wait for a key: **gen3, tiles and swing** (named by the EP, 2026-10-31; owners World and Rendering). A row with no `file` is a name only. When the owner lands the key, give the row `file`, `path`, `from` and `to` (and `needs`, `probe`): it becomes a switch, on by default, `--off`-able and checked.
- **`--overlay <paths>`** (comma-separated, relative to the repository root, existing) copies those paths of the WORKING tree over the scratch copy: for work that is not committed yet (Controls' right hand before it lands). The report says `OVERLAY: ... uncommitted`, `build_info.json` lists the paths, and the cache key holds a hash of their contents (a change to a file builds again). It reads files as they are on disk, so mid-edit work builds mid-edit.
- **`--open`** opens the printed address in the default browser once it is served (Windows `start`); without it nothing opens.
- **What the right hand does in the game today** (Controls' README, `docs/controls/pending/right-hand/README.md`): the input layer is built (the stick, the strike reader, the left hand's brace and vanish, the swapped layouts, the D-pad mirror), but the **simulation and the director do not read the intent's second word yet** (`SimIntent.pack2`, `rsStart`, `rsRelease`, `rsLevel`, `rsDir`), nothing outside `sim/input/` uses them, and the settings screen has no rows for it. With the switch on the right stick is read and shapes the intent, and **the fight does not change** until Simulation and Encounter consume it. The preview turns the switch on honestly; it cannot make the fight use it.
- `--check` now says what it did NOT check: what waits, and that an overlay is uncommitted work.
- Self-test: `node tools/preview/preview-selftest.mjs` (96 checks).

## The stack: HEAD plus every park, before anyone lands anything (the EP, 2026-10-31)

`node tools/preview/stack.mjs` takes the commit and the parks of `tools/preview/stack.json` **in the order they must land**, puts them in ONE scratch export, and says whether they fit together:

- **the first conflict, by file and owner**: each park's steps are applied in order (`patch`: git apply of a file in the working tree; `copy`; `overlay`: an owner's uncommitted folders laid over the commit; `manual`: a note, never run). A step that does not apply names the file, the park that touched it earlier (or "the commit itself": HEAD moved since the park was made), the file's owner (from the charters' `owns:` lines) and the park's owner. A conflicting park is left out and the stack goes on, so one report shows every conflict. An overlay that would overwrite a file an earlier park changed is a conflict too. A patch already in the tree (it reverses cleanly) is "landed", not a conflict;
- **every switch on**: the preview's switches, the pending rows' that have keys, and those a park adds (`switches` in its entry); the ones whose key is not in the tree wait and are listed;
- **validate** (`tools/validate.js` in the scratch tree), each error attributed to the park that touched its file;
- **a `script` step** for a park that ships an install script (Simulation's field-frame): it runs ONLY when the file is exactly the one Tools reviewed (its sha1 is in the manifest, so an edited script shows as `unreviewed` until Tools has read it again), with the scratch tree as its one argument, python in isolated mode; never on the repository; a script that stops half-way is a conflict and says what its assertion expected;
- **two labelled bridges** between parks that disagree, until their owners re-cut one: a `fixup` step (`{file, from, to, count}` and a `why`: the text must be in the scratch tree exactly `count` times, else the step is a conflict, so a stale bridge cannot pass) and a patch step's `exclude` (`git apply --exclude`, with a `why`: a hunk two parks both carry). Both print in the report as FIXUP and EXCLUDING with their reason, in every run; they never touch the repository;
- **the extra matches** when the tree has the code: `smoke_match.gd --planet-gen=3` (World's field: a whole ring on gen 3, when `sim/world/field.gd` exists), `--tiles` (Rendering's tile ground on that gen 3 ring, when `render/core/tile_ground.gd` exists) and Research's swing probe (`research/ring-any-angle/swing_smoke.gd.txt` from the live repository, copied into the scratch tree only: a launch-sized swing asked every 300 ticks on gen 3, when the tree declares `SimSwing`); each is reported and attributed apart. The preview's `gen3` (a setup key: `planetGen` 3), `meteor` (VFX's page word: `?meteor=loud` by default, with `?meteor=quiet` printed beside it; local pages only) and `tiles` (the page word `?tiles=1`) switches are on in the stack when the tree has the code each needs;
- **the import** of the project and **a smoke match**, headless: `tools/preview/smoke_match.gd` plays an AI match on a generated planet for 900 ticks through the real scene (the way tools/flash/flash_worst.gd builds it); a `SCRIPT ERROR` anywhere is attributed to the park that touched the `res://` file in its `at:` line;
- **what each park needs that is missing**: `needs` in the manifest: a park that did not apply, a file, a text in a file, or a known gap that is not in the tree (a note with its owner, listed until the manifest drops it).

```
node tools/preview/stack.mjs                 the whole run: about 6 minutes (the unpack, validate, the import, the smoke match)
node tools/preview/stack.mjs --no-godot      the apply, the switches and validate only: about 10 seconds, for the hourly look
node tools/preview/stack.mjs --list          the parks in order, with owners and whether each is ready
node tools/preview/stack.mjs --only a,b --skip c --include-unready --ticks 1500 --force --keep-tree
node tools/preview/stack-preview.mjs         a PRIVATE, LOCAL, playable web build of the stack, every switch on (below)
node tools/preview/reel.mjs --dir <the page's web folder> --out <folder>     a reel: a real AI match stepped on the page, stills with the swing's state (below)
node tools/preview/bisect.mjs --check anim|cover|lake|<res://check.gd>      the first park a headless check fails on (below)
```

**`?swings=off`** (Encounter's page word, 2026-10-31): when the stacked tree has `DirSwing.setForce` (Encounter's swing park), the scratch `render/core/main.gd` gets a `_preview_swings_off()` called before each match starts: on a **local page** (127.0.0.1 or localhost) whose address has `swings=off` it calls `DirSwing.setForce(0)`, so the choreographer asks for no swing. The printed addresses then include it (`DirSwing off (Encounter's page word): ...&swings=off`). Checked on the build: 0 swings in 1,515 ticks against 3 in the plain address's smoke window.

**Gates that read the switches as shipped (Combat, 2026-11-01):** the stack turns every preview switch ON in its scratch tree, and **golden (`sim/core/tools/parity.gd`) and `launchbiome_probe`** check the switches as shipped: with them on, golden fails 8 rows and launchbiome 1 row **on main alone**. So do `cover_water_check` and `lake_water_check` (2 each, the "gen 1 planet" rows, with `gen2` on) and `anim_check` (13, with `floor`, `surface` and `interrupts` on). The stack does not run them, every report ends on a note saying so, and `bisect.mjs` runs these five with the switches OFF by default and refuses them with switches on unless `--with-switches-anyway` (a trace of which switch does it). A failure of one of them on a stack tree is not a park's.

**The defaults are read back** (the EP, 2026-11-01, for Orb's `Open - playable.cmd`): the state probe reports `rightStick` (`SimInputData.right_stick_on()`), `swingOn` (`DirSwing.on(S)`: the data flag and a field world) and `stickOn` (`DirStick.on()`), the smoke check prints them (`DEFAULTS READ FROM THE RUNNING GAME: right hand ..., DirStick ..., DirSwing ...`) and fails a page whose probe reads one off while its switch is on, naming the switch. **`?sticks=1`** (local pages only, with `DirStick` in the tree): player 1 is claimed by a scripted pad whose right stick is driven by the scratch main.gd every tick (a quick flick at phase 30 and a held charge at 120 to 170 of every 240 ticks, the direction turning each 240), so an AI match shows stick strikes; the probe counts the stick cues as `stk`; the reel's `--sticks` asks for it. **`nofore=1`** (Rendering's tile.diff) turns the fore tone off to compare; the address list prints it.

**The reel** (`tools/preview/reel.mjs`, the EP, 2026-10-31: a pane that is hidden cannot run the page): the page's build is stepped one tick a frame through the guarded launcher with the flash capture hook (`?flashcap=1`, the `ai` scenario, a real AI match on the page's planet) while the page's state probe (`?preview=1&reel=1`, published every frame) says what the swing and the fighters are doing. A still every 30 ticks, kept within 60 ticks of a swing or a launch, until it has seen two swings and a launch (`--swings`, `--launches`, `--cap`). Output: contact sheets (the tick, SWING ON with rate, degrees left and cause, the fighters' states, a LAUNCH mark in each still's corner), `reel.json` and the JPEGs. Private: nothing is published.

**The bisect** (`tools/preview/bisect.mjs`, the EP, 2026-10-31): a headless check (anim_check, cover_water_check, lake_water_check, or any `res://` script that prints `FAIL  ...` lines and exits non-zero) is run on the commit alone and on the commit plus the first k parks, binary search, and the smallest k where it fails names the first park that causes it, with the failing lines and the ones new against k-1. One scratch tree and one Godot job at a time, below-normal priority. It assumes the check keeps failing above k; the probes printed are the evidence. **The preview's data switches are on in every probe by default**, so a check that fails at k=0 fails on the commit with the switches alone: `--switches none` (or a list, `--switches gen2` or `--switches surface,interrupts,floor`) varies them, which is how the 2026-10-31 failures were found to be the switches' (`gen2` for cover_water and lake_water, `floor` with its two needs for anim_check) and not a park's. The reel's probe also carries `S.pause.left`, `S.dirS.stop` and `SimSwing.movingNow(S)` (when the tree has it). **The stack also runs Rendering's `render/tools/tile_check.gd` headless** when the tree has it (tile.diff adds it), reported as `Tile check`.

**The stack's preview** (`tools/preview/stack-preview.mjs`, the EP, 2026-10-31): the stack's scratch tree (parks applied, switches flipped) gets the same scratch `render/core/main.gd` entry and state probe as `preview.mjs` (and Controls' host patch if the tree lacks the pad's right stick), is imported and exported to Web with the standard template at below-normal priority, passes the same boot-and-play smoke check through the guarded launcher, and is served on 127.0.0.1 only. It prints the address (the page words of the page-word switches, `?tiles=1`, are in it). `--template custom|standard|<zip>` (default **custom**: the page is exported with the engine template the site serves, the pinned zip of `tools/web-template.json` read from a verified copy on disk, else downloaded and checked by `tools/site-template.mjs`; a path is a scratch template of our own, used as it is; only the scratch tree's copy of the Web preset changes; the template is part of the build's cache key), `--planet 7 --port 8766 --off tiles,meteor --skip park,park --rebuild --no-smoke --no-serve --open --watch --every 120`; **`--watch`** keeps the page current: it serves a stable folder, reads the stack's key (the commit, the bytes of every park file and the manifest) every `--every` seconds (at least 30), and when it changes applies the stack again, builds, smoke-checks and swaps the new build in under the same address; one build at a time, and a build that fails its smoke check leaves the page as it was. **Limits (the EP, 2026-10-31, a saturated machine):** at most one rebuild per `--min-gap` seconds (default 1800) and none while the machine's CPU is above `--max-load` percent (default 90, sampled over a second at each tick); a change that arrives inside the gap or under load is kept and built at the first tick that is allowed, and the log says why it waits (once per change); builds run at below-normal priority with one capture; a busy port that is named is an error, an unnamed one falls on to the next. Never published, uploaded or dispatched.

It prints what CHANGED since its last run (the first conflict, each park's status, validate, the import, the smoke match, the count of things still needed), keeps the last report in `%TEMP%\meridian-stack\last.json`, and does no work at all when nothing it is made of (the commit, the bytes of every park file) has changed. It reads the repository and writes only under a scratch folder under the temp folder (a scratch folder that is the repository or inside it is refused), runs one Godot at a time at below-normal priority, and never runs an apply script. Parks marked `"ready": false` (unfinished, by their owners' own READMEs) are left out unless `--include-unready`. The manifest is Tools' to keep from the parks' READMEs: when a park appears, add it; when its order changes, move it. Self-test: `node tools/preview/stack-selftest.mjs` (41 checks, no Godot).

**The tools:**
- `node tools/preview/stack.mjs [--no-godot]` applies the manifest (`stack.json`) in order and names the first conflict; `ready: false` leaves a park out; a `patch` step may carry `exclude` and a `why` for a file that two parks both change.
- `node tools/preview/reel.mjs --dir <build> --out <folder> --sticks` plays a real AI match through the capture hook, a still near each swing and launch, and counts the stick cues; `--swings`, `--launches`, `--cap`.
- `node tools/preview/playtest.mjs --dir <build> --query "<words>" --script steps.json --out <folder> [--probe]` plays the page as a person meets it, with a scripted pad (connect, tap, stick, click) and a screenshot per step; the console lines go in the record.
- `reel.mjs --sticks2 --until-clash` plays two scripted pads and stops after the first beam clash; `--wall-check` measures the longest run of ticks either fighter stands behind a building (`PaneWorld.occluded`) and exits 3 over 180 ticks (3 s): the regression test for the wall bug.
- `node tools/preview/blackbox-verify.mjs <file> --tree <stack tree>` re-runs a saved black box file through `SimReplay.play` headless: BLACKBOX OK ticks=N final=<hash>.
- The wall check has two readings: `occ` (the index's candidates, `PaneWorld.occluded`) and `occAll` (every building at the height the view DRAWS it: Rendering's band rule is in the shader, so the probe replays its rest part; a building drawn down to its base of 90 units or less is not a wall; in a build without the band park every building is drawn whole). `record.wallDrawn` carries the second; `--wall-check` fails on either.
- Everything runs through `tools/machine`'s guarded browser launcher, below-normal, one at a time.

**What a person presses today** (the live page, 2026-11-01, software rendering so the first load is about 45 s): "Preparing the graphics"; the notice card (click Start, or D-pad Down, Right for Controller, Down seven times, A); with `go=1` the fight begins within about 10 s and player 1 is the pad. Start on the pad opens the pause menu.

**The black box (the EP, 2026-11-01):** `blackbox=1` records the presses, the seed and the setup of the match in the project's own replay format and, at the KO or when a match is left for a new one, shows a card with three optional questions and a "Save my match file" button (a download to Downloads). It only reads (the same `SimCore.step` call with the same inputs), sends nothing anywhere and is off without the word. `tools/preview/blackbox.mjs` has the hooks and the page script; a copy is also kept in the browser's own storage so a closed tab can still offer the last record. **Slow frames (2026-11-01, render side only):** the page times the browser's own gaps between frames and keeps, for the match in play, every gap over 33 ms with the tick the game was on (`window.__bb_t`, set once a frame by the host hook) and the seconds in, plus the counts over 33, 50 and 100 ms and the worst; gaps over a second (a hidden tab, a sleeping PC) are counted apart. The card says it in a line, the saved file carries it as `frames`, and the playback clip writes each slow frame on the picture where it happened and lists them under the player. All of it is in the page script; the sim and its hashes are untouched. **The KO is `S.game.ko`** (the first cut read `S.ko`, which is not a field, so a real KO was never seen: `blackbox-ko-check.mjs` plays a full-power match to a real KO and saves what the page would save). The build's key includes the preview tools' code, so a change to them always rebuilds. (The key is hashed as a whole, with a readable tail: it was once cut to its last 120 characters, which dropped the stack's part and let two different stacks share a folder.)

**The reels for the first-press list (the EP, 2026-11-01; `docs/ep/first-press-list.md`).** All through the capture hook, below-normal, one at a time. `reel.mjs` flags: `--keep-all` (every still), `--dense` (contact sheets of 60 thumbnails, 6 across, in tick order), `--limit <s>` (the browser's time limit), `--rematch` (a new match after a KO or a match that does not end in 7,200 ticks, so ten minutes of play are one run; each match is listed in reel.json with the black box's own state), and the page's console errors and exceptions recorded with their tick (exit 4 when there are any; the static server's 404 for the manifest and favicon is left out). The record also carries `positions` (a row per still: both fighters' world x and height) so a place can be named to Rendering.

`blackbox-ko-check.mjs --dir <build> --out <folder> [--query ...] [--seed N] [--max N]` plays the hook's match until the black box queues an `over` match and saves what the page would save; with none it prints the box's own state. `playtest.mjs` has a `snap` step (the black box's frame and right-stick record). **The black box's raw right stick:** the first connected pad's axes 2 and 3 (the standard mapping), a sample `[tick, ms, x, y]` each frame the stick is off centre and the frame it returns, saved as `rawRightStick` in the same local file; read only, nothing leaves the PC. **A cached build is keyed by the stack, the switches, the preview tools' own scratch code (`switches.mjs`, `blackbox.mjs`, `preview.mjs`) and the probe list**: a reel reading a probe the build lacks, or a pad mode the build lacks, was once silently run on an older build.


## v5 additions (Tools, 2026-11-01, after Orb's first play)

**Sound, as the page tests it.** `?audiolog=1` or `?blackbox=1` turns on the sound log (before, only `audiolog=1` did, so Orb's first file read `audio.on: false`). It taps every context the page makes (state, `currentTime`, the first sound, a 40 ms analyser at the destination), counts the cues the game handed to its voices (`window.__audcue`: taken and dropped), the rumble the game asked for (`__vibreq`) and what the browser was asked (`navigator.vibrate`, `playEffect`, `pulse`), and keeps the cue times and the loud-window times so a delay can be read (a cue to energy at the destination). A trusted pointerdown, keydown or touchstart resumes any suspended context. With the word `audiolog=1` a small line shows at the bottom left: `sound <state> t=<currentTime> played <n> dropped <n> out peak <0..1>`. The engine's own bus meters are read with `audiolog=1` as well (`engineMixer`, per frame, read only). `window.__audio_snap()` returns it all; `playtest.mjs` has `audio` and `eval` steps and `reel.mjs` writes `audio.json` and a summary into `reel.json` when its `--query` carries `audiolog=1`.
**Sound modes.** The web default plays an `AudioStreamPlayer2D` as a Sample, outside the mixer; in headless Chrome and Opera GX it reads silent at the destination on a plain HEAD build, Stream (`audio/general/default_playback_type.web=0`) reads real sound. The manifest's park `sound-stream-mode` makes that line in the build only (a fixup on `project.godot`); `--skip sound-stream-mode` builds the Sample variant. `PLAYTEST_NOMUTE=1` runs `playtest.mjs` without `--mute-audio` (with `--disable-audio-output`, a null sink: nothing sounds on the PC); the launcher otherwise always sets `--mute-audio`.
**Switches.** `soundTug`, `soundMoments` (+ `audio-moments`, Audio's install script, hash-locked), `soundCarry` and `webRumble` (Controls' `web-rumble.patch`: the page asks the pad's `vibrationActuator` itself). The probe reads each one back from the running game. `soundMoments` and the bright bolt need `audio/tools/host_check.gd` (the park `audio-host-check` lays the working-tree copy over the tree).
**The black box takes no mid-match checkpoint hash** (Performance: 38 to 58 ms a hit in the page). The final hash at the KO proves the replay; `blackbox-verify.mjs` prints `BLACKBOX OK-UNCHECKED` for a match left before its KO (it replays, nothing to compare). `blackbox-clip.mjs` takes `--from N --to N`: pictures only from N, the match played no further than `--to`.
**`stack-preview.mjs --rev <sha>`** builds a stack on that commit (the default stays `main`); with `--keep-tree --out <scratch>` it leaves the tree for a replay on exactly the page's key.
**Reel cut finder** (`reel.mjs`): the mean frame change from still to still; `reel.json` `cutCandidates` lists the biggest, with both fighters' states.

**v6 additions (Tools, 2026-11-01).** `reel.mjs --hold 541,3301 [--hold-for 60] [--hold-every 6]` pauses on a tick (the sim is not stepped; the page keeps drawing) and takes a still every few seconds for a minute, with the mean change from still to still in `reel.json` `holds` (stills in `<out>/holds/`): ground that stays reads as a change near 0. `blackbox-clip.mjs --hold-at N` does the same on a tick of a recorded match. The page word `?splitshare=N` sets Camera's split share each frame (0.5 against the default 0.7). Parks added to the manifest: Camera's swing-share and lead-ahead (+ a fixup turning `lead_ahead` on), Encounter's beam-still, ground-settle, swing-warm, Simulation's field-place (+ Encounter's standing grant), Controls' first-pad, Audio's status line, Rendering's p to t (tile pool, coarse first, fill slice, tile level word, tundra strata) and Art's `data/art/biomes.json` overlay; the switches `splitShare` and `settle`.

**The energy model on the page (Simulation's power-core, off by default).** `?power=1` puts `"power": true` in a match's setup (data/fight/power.json stays off); `?flatout=N` (3,500 to 7,000, the data's own range) or the slider shown with `?power=1` (bottom right, remembered in the browser, read at the start of the next match) sets `"flatOut"`, the base of flat-out flight.
