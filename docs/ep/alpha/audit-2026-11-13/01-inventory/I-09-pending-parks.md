## Method (what was checked, exactly)

There are well over 400 items, so the check was done park by park, not file by file.

1. **Every patch or diff file** under `docs/*/pending` (257 files, tracked and untracked) was tested against HEAD's index with read-only `git apply --cached --check -R` (reverse applies, so it is **ON MAIN**) and then `git apply --cached --check` (forward applies, so it is **STILL WAITING, applies clean**). Nothing was staged (`git diff --cached` was empty), so the index is HEAD. Totals: 70 ON MAIN, 28 APPLIES, 159 NEITHER.
2. For the 159 NEITHER files, up to 8 added lines (longer than 35 characters, sampled 1 line in 7, comments skipped) were searched verbatim in HEAD outside `docs/` with `git grep -F`. Results: 79 had all sampled lines present (**likely on main, then drifted**), 53 had some, 26 had none (**not on main**), 1 had no sample lines. Lines that match by chance are possible, so "some" means unclear.
3. **Full-file parks** (audio `src/`, director `files/`) were compared byte for byte with HEAD at the same path after stripping CRs.
4. **Data parks** (narrative and combat JSON) were matched by file name under `data/`, and narrative values were searched in HEAD.
5. **Edit-script parks** (director `*.cjs`, tools `apply-*.cjs`) were checked by searching HEAD for the backticked camelCase or underscore keys their README names (up to 12 keys a park) in sim/data/render/ui/tools, or for the keys their index names.
6. Commit messages were searched for park names (`git log --grep`). This found little, because commits are written in prose.
