# Adversarial review: what conflicts with the PC, safety and Legal rules

Alpha audit, phase 6, 2026-11-13. Read-only. One lens: does the path or any brief break a machine rule, hand a build to an outside tester too early, put something in public without Orb, leave an account or upload to the wrong hand, let personal details into the repository, or touch the one delegated topic (flashing) in a way it should not.

Paths are relative to `docs/ep/alpha/audit-2026-11-13/` unless they start at the repository root. "Path" is `04-path-to-alpha.md`. Weight: serious (the Alpha would ship wrong, or a rule that protects a person breaks), moderate (a milestone slips or a brief misleads), small.

## What I looked at, and what I did not

Read whole: the path; the Legal area page with its gate list G1 to G20; `questions.md`; `07-skipped.md`; all six `orb.md` pages; the EP's briefs for A1 to A4; Legal's briefs for A1 to A4; Tools' briefs for A1 and A2; Performance's, Production's, Community & Marketing's and Camera's A2 briefs; Narrative's and part of UI's A5 briefs. Read by search across all 100 briefs: every line about itch.io, uploads, keys, friends, the approval file, the firewall and real-socket checks, windowed or desktop runs, git state, process counts, direct contact between directors, and gate re-runs. Scripts: each brief's "You own" line against the roster in `DIRECTORS.md` (all match); paths a brief saves to against its owned and granted paths (no ungranted write found); the register for rows tying a flash reading to a desktop build (none); the untracked tree by file type and folder, with counts only for home paths (0 files) and private network addresses (2 files, both inside this audit's own folder). Read from the project: `.github/workflows/desktop-builds.yml:1-61`, the tester note, `name-screening.md:180-190`, the camera park's page, the header of `tools/flash/release-pass.mjs` and of `tools/machine/capture.mjs`, `.gitignore:20-40`.

Found clean, so not listed: no brief asks a director to change git state, to message another director, or to exceed the process caps; the real-socket check is kept in CI in every Netcode brief; the trusted-two and outside-tester packages are kept apart in A3; no question about flashing appears in the decisions table.

Not done: the other 60 or so briefs were not read line by line, only searched; A3 to A6 briefs outside EP, Legal and Tools were sampled. No Godot, browser or web was used, so nothing about itch.io, Discord or GitHub was checked beyond what `web-checks.md` and the workflow's own header say; in particular, that run files on a public repository can be fetched by others is taken from the workflow's header and should be confirmed by the EP. The public state of the repository is taken from the audit's own pages, not from the host. I did not read the 13,000 untracked pictures, so which of them show in-progress character art is not known beyond the folder names.
